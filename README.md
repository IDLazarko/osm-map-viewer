# 🗺️ OpenStreetMap Local Viewer (OSM Server)

Консольное приложение на **C# (.NET)** для безопасного локального просмотра интерактивных HTML-карт (например, сгенерированных через Python-библиотеку `folium`).

## ❓ Какую проблему решает проект?

Серверы OpenStreetMap блокируют отображение плиток (тайлов) карт, если открывать файлы напрямую из папки через браузер (по протоколу `file:///`). Это происходит из-за отсутствия HTTP-заголовка `Referer`.

Данное приложение **автоматически поднимает локальный веб-сервер**, транслирует карту через безопасный протокол `http://localhost:8000` и само открывает браузер. В таком режиме заголовки передаются корректно, и карта **никогда не блокируется**.

---

## ✨ Ключевые фичи

* **Авто-сканирование:** При запуске программа сама находит все файлы с расширением `.html` в текущей папке и выводит удобное пронумерованное меню.
* **Поддержка пробелов:** Корректно обрабатывает любые сложные имена файлов, содержащие пробелы и спецсимволы.
* **Умное авто-закрытие:** Как только вы закрываете вкладку с картой в вашем браузере, сервер фиксирует разрыв соединения и **автоматически закрывает окно консоли** через 2 секунды. Никаких лишних действий!
* **Абсолютная автономность:** Скомпилированный `.exe` файл не требует установки .NET на целевом компьютере коллеги и не вызывает подозрений у антивирусов Windows Defender.

---

## 🚀 Как использовать

1. Положите файл `MapViewerProject.exe` (можно переименовать) в папку, где хранятся ваши файлы карт (`.html`).
2. Запустите файл двойным щелчком мыши.
3. В появившемся окне введите **номер нужной карты** из списка и нажмите `Enter`.
4. В браузере автоматически откроется рабочая карта.
5. После окончания просмотра просто **закройте вкладку в браузере** — программа закроется сама.

## 🛠️ Как собрать проект самостоятельно (Self-Contained EXE)

Для перекомпиляции проекта в один независимый исполняемый файл выполните в PowerShell команду:

```bash
dotnet publish -c Release -r win-x64 --self-contained true /p:PublishSingleFile=true /p:PublishTrimmed=false
```
Готовый файл будет находиться по пути: `bin/Release/net10.0/win-x64/publish/MapViewerProject.exe`.

## 🏗️ Что нужно для компиляции и порядок сборки

Проект написан на чистом C# и использует исключительно стандартные системные библиотеки .NET (пространства имен `System.Net`, `System.Diagnostics`, `System.Threading` и др.). Никаких сторонних внешних библиотек (NuGet-пакетов) скачивать не требуется.

### 🧰 Системные требования для сборки:
* **.NET SDK 10.0** (или .NET 8.0 / 9.0) — официальный пакет разработчика от Microsoft.

### 📋 Пошаговый порядок компиляции консольного приложения:

Если вы хотите собрать этот проект с нуля на новом компьютере через терминал (PowerShell или CMD), выполните следующие шаги:

1. **Создание шаблона проекта:**
   Откройте терминал в нужной папке и создайте заготовку консольного приложения:
   ```bash
   dotnet new console
   ```

2. **Размещение кода:**
   Замените стандартный автосгенерированный код в файле `Program.cs` на исходный код сервера из данного репозитория.

3. **Компиляция (сборка):**
   Для сборки консольного приложения существует несколько подходов в зависимости от ваших целей:

   * **Вариант А: Обычная сборка (Зависимая от среды)**
     Создает легкий `.exe` файл, но для его запуска на компьютере пользователя обязательно должен быть установлен .NET Runtime.
     ```bash
     dotnet build -c Release
     ```

   * **Вариант Б: Автономная сборка (Self-Contained) — РЕКОМЕНДУЕТСЯ**
     Компилирует приложение в **один независимый файл**, внутрь которого упаковываются все необходимые системные библиотеки .NET. Такой файл запустится у коллеги без установки каких-либо дополнительных программ.
     ```bash
     dotnet publish -c Release -r win-x64 --self-contained true /p:PublishSingleFile=true /p:PublishTrimmed=false
     ```

4. **Поиск готового файла:**
   После успешной автономной сборки исполняемый файл `.exe` будет ждать вас в целевой папке публикации:
   `bin/Release/net10.0/win-x64/publish/`

5. ** В случае ошибки и для перекомпиляции выполните следующие шаги по очереди: **

   Шаг 1. Полностью очистим старые файлы

   ``` bash
   Remove-Item * -Recurse -Force -ErrorAction SilentlyContinue
   dotnet new console --force
   ```
